# AI Work Hub — CodexからClaude Codeへの修正依頼

## 最優先の再確認

利用者が本当に減らしたいのは記録作業ではなく、AIを乗り換える摩擦です。

普段の流れは、ChatGPTで考える → 実装が必要ならCodex → 検証ならClaude Codeです。
AI Work Hubは会話管理ツールとして複雑化させず、「渡す」操作を最短にしてください。

## 期待する基本操作

1. 利用者が会話・要約をAI Work Hubへ貼る、または話す
2. 「Codexへ渡す」または「Claude Codeへ渡す」を1回押す
3. 引き継ぎ文を自動生成してコピーする
4. 送り先がスマホで開ける場合だけ、そのアプリ／ページを開く
5. 利用者は貼り付けて送信する

「今日はここまで」は補助機能であり、毎回の保存・分類を要求しないでください。

## Codexについて

Codexはculone-server上のデスクトップアプリで利用しており、スマホから開くための固定URLはありません。

- CodexのURL登録を必須にしないでください。
- 「Codexへ渡す」は、引き継ぎ文をコピーできれば完了です。
- 画面には「CodexをPCで開いて貼り付けてください」と短く表示してください。
- URL不明をエラーや設定不足として扱わないでください。

Claude Codeだけは、利用者が実際に使う開き先URLを設定できる形で構いません。

## 実装レビューで直してほしい点

### 1. HTTPスマホ画面でのコピー失敗

家庭内の http://192.168.0.7:8787 では、ブラウザーのクリップボードAPIが使えないことがあります。

コピーに失敗しても、引き継ぎ文を編集不可の textarea に表示し、長押しで確実に手動コピーできるようにしてください。divに表示するだけでは不十分です。

### 2. ローカルLLM待機中のロック

server.py はローカルLLMのHTTP応答待ちを threading.Lock の内側で行っています。その間、他の会話の閲覧や保存も止まります。

会話を保存してからロックを外し、LLM呼び出しはロック外で行ってください。応答を書き戻すときだけ、短時間ロックを取る設計にしてください。

### 3. ローカルLLMの仮設定

現在の ai2.local と llama3 は仮設定です。実環境ではAI2は 10.10.10.2:11434、利用モデルは実在するOllamaモデル名を使います。

設定を決め打ちで上書きせず、接続先・モデル名を設定画面または既存保存データから確認・編集できる形にしてください。

### 4. 既存データを置き換えない

culone-serverで既に動いている旧AI Work HubはSQLite保存です。今回のJSON保存版へ切り替える前に、移行方式とバックアップを用意してください。

既存の ai_work_hub.sqlite3、会話Markdown、家庭内ネットワーク設定を削除・上書きしないでください。

## 完了条件

- ChatGPT等からの会話取り込み → Codexへの引き継ぎ文生成まで確認する
- Codex URLが空でも引き継ぎ操作がエラーにならない
- コピー不可の端末でも、画面上で長押しコピーできる
- Claude Codeの開き先URLは任意設定として動く
- ローカルLLM応答待ち中でも受信箱の操作が止まらない
- 変更前後と確認結果を、短くCodexへ返せる形で報告する
