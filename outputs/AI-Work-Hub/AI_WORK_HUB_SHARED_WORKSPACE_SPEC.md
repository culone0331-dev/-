# AI Work Hub 共有作業台帳 仕様書

## 1. 目的

AI Work Hubの目的は、会話を記録すること自体ではない。

利用者がChatGPT、Codex、Claude、Claude Code、ローカルLLMを行き来しても、同じ案件の目的・原文・判断・未確認点・回答を失わず、次のAIへ渡す摩擦を最小化することである。

利用者は主にスマホで思いつきを話す。ChatGPTで考え、実装が必要になればCodexへ渡し、検証はClaude Codeへ渡す。この移動のたびに説明を作り直させない。

## 2. 重要原則

1. 案件ごとに一つの共通台帳を持つ
2. 利用者の原文と各AIの回答を改変せず残す
3. AIが作った短い要約を唯一の正解にしない
4. 要約、判断、未確認点は原文と分けて版管理する
5. 毎回の分類、終了宣言、長い入力を要求しない
6. 外部AIへの自動送信ができないことを隠さない
7. 既存データ、家庭内ネットワーク、AI2設定を壊さない

## 3. 最小の利用者操作

### 思いつきを残す

利用者は一つの入力欄で話すか書く。案件名や担当は空でもよい。

保存後、AI Work Hubは新規案件または既存案件へ原文を追加する。利用者に毎回整理を求めない。

### 次のAIへ渡す

案件画面で、Codexへ渡す、Claude Codeへ渡す、ChatGPTへ渡す、ローカルLLMで確認する、のいずれかを押す。

その時点の案件情報から、引き継ぎパッケージを自動生成する。

- 案件の目的
- 利用者の原文
- 現在までのAI回答
- 決まったこと
- 未確認点
- 次に依頼すること
- 作成日時と版番号

スマホで開ける外部AIは、コピーと開き先への遷移をできるだけ一回の操作にまとめる。

CodexとClaude Codeのデスクトップアプリは、スマホから確実に起動・投稿できない。したがって、引き継ぎパッケージを確実にコピー可能な状態にし、PC側で貼り付ける操作だけは利用者が行う。URL登録の有無を必須条件にしない。

## 4. 案件の構造

各案件は次の情報を持つ。

| 項目 | 内容 |
| --- | --- |
| 案件名 | 空でも開始可能。後から自動候補または手入力で変更可能 |
| 目的 | この案件で最終的に達成したいこと |
| 原文ログ | 利用者の発言を時系列で保存 |
| AI回答ログ | ChatGPT、Codex、Claude、Claude Code、ローカルLLMの回答を原文で保存 |
| 判断ログ | 採用した方針と理由 |
| 未確認点 | 推測で進めてはいけない点 |
| 現在地 | 今どこまで終わったか |
| 次の担当 | 次に確認または実装するAI |
| 引き継ぎ版 | いつ、どの内容を、どこへ渡したか |

AIの回答を取り込むときは、ChatGPT、Codex、Claude、Claude Code、ローカルLLMという出所を付ける。利用者の原文と混ぜない。

## 5. 引き継ぎパッケージ

引き継ぎパッケージは、毎回一から要約を書かないための自動生成物である。

同一案件の同一時点から生成したパッケージには版番号を付ける。送り先と生成日時を記録する。

受け取ったAIは、パッケージに対する回答を返す。利用者はその回答を案件へ貼り戻すだけでよい。AI Work Hubは回答の出所と時刻を保存する。

## 6. 画面の優先順位

最初に見せるのは案件一覧と、すぐ話せる入力欄である。

案件を開いたとき、最初に見せるのは次の3つである。

1. 今の目的と現在地
2. 最後の利用者発言と最後のAI回答
3. 次の操作ボタン（Codex、Claude Code、ChatGPT、ローカルLLM）

設定、詳細な履歴、アーカイブは二次画面へ置く。引き継ぎを作る前に、複数の選択欄を埋めさせない。

## 7. ローカルLLM

ローカルLLMは外部AIへの引き継ぎと違い、AI Work Hubから直接呼び出せる。

ただし接続先とモデル名は仮値で固定しない。culone-serverとAI2の実在するOllama接続先・モデル名を確認して設定する。

ローカルLLMの応答待ちで、他の案件の閲覧・保存を止めない。ネットワーク待機は保存用ロックの外で実行する。

## 8. データ保全と移行

現在の稼働版はSQLite保存である。新しい実装へ移行する前に、次を必ず行う。

1. 現在のSQLiteデータベースと会話Markdownをバックアップする
2. 旧データを読み取り専用で監査する
3. 変換結果を別保存して検証する
4. 旧版を上書きせず、別ポートまたは別フォルダで新実装を検証する
5. 利用者が確認してから切り替える

## 9. 今回の実装対象

最初の実装では、以下だけを確実に作る。

1. 案件ごとの原文・AI回答・現在地・未確認点の保存
2. 出所を付けたAI回答の取り込み
3. 版番号付き引き継ぎパッケージの生成
4. Codex、Claude Code、ChatGPT、ローカルLLMへの次操作を選ぶ画面
5. 既存SQLiteデータを失わない移行計画

外部AIへの自動投稿、アカウントの自動同期、既存チャットの自動選択は今回の対象外とする。

## 10. Claude Codeへの依頼

この仕様書を基準に、現在のAI Work Hub実装を見直してください。

- 記録中心の画面ではなく、案件の現在地と次のAIへ渡す操作を中心に再設計する
- 原文とAI回答を分け、出所と時刻を保存する
- 引き継ぎパッケージを版管理する
- 既存SQLite版を消さず、移行案を先に提示する
- 実装後は、ChatGPT由来の内容を取り込み、Codex用とClaude Code用の引き継ぎを生成し、回答を貼り戻す一連の確認を行う

不明な点は推測で仕様を増やさず、利用者へ確認すること。
